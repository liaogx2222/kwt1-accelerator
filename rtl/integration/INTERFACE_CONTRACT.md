# 固定 RTL v2 接入契约

固定 8×8、20×4096×16 同步单口 SRAM 和 INTEGER_NUMERICS_V1。硬件源及寄存器 ABI 沿用 [v2](../v2/README.md)，候选软件使用本目录 `driver/kwt1.h/.c`。旧驱动保留供来源与 A/B，不混用两版 C 结构体。以下是逻辑时序与回调契约，不是指定库的 ns 时序或真实 E203 周期证明。

## 总线

- 单时钟、32-bit、小端、4-byte 对齐，只支持完整字写入。请求在 `req_valid && req_ready` 的上升沿接受；未接受时源保持全部字段稳定。
- 一笔在途响应。`resp_valid && !resp_ready` 时 data/error 保持；旧响应消费与新请求接受可以同拍发生。消费旧响应不能清掉同拍新建的响应。
- DATA(参数0x10、输入0x14、输出读0x18) 自带 ready 背压。不能把 `req_valid` 发出当作写入已完成，也不能把未完成响应归给下一请求。
- 最后输出请求接受时数据被捕获，直到其响应消费才向加速器确认；此前不允许 done/IRQ。软件完整窗口还包括输出写入目标数组和 done 读取，到驱动返回结束。
- 软件 ABORT(0x00 写2) 的本次响应保留；内部 abort 在该请求被接受的边沿后有效。最终输出 ACK 与 ABORT 同拍时，旧响应完成，随后任务状态被清除；不能把该边沿的 done 当作下一任务完成。外部 `abort_hw` 或 `rst_n=0` 直接取消在途响应，并阻止同拍新请求接受。
- 硬复位丢弃的事务必须由平台传输层作废，不得在下一任务重新交付旧响应。复位异步断言，释放由集成层同步；硬件没有跨时钟域适配。

寄存器含义见 v2 README。STATUS 的 busy/done/error/有效槽/层需求为 bit0…7；frame_ready 为 bit9。软件 ABORT 确认要求这些低八位全清且 frame_ready=1；ID(0x48)为0x4b575431。CRC 成功发布与层序仍是独立检查，不靠总线 ACK 替代。

## 阻塞回调与超时

`read/write` 回调必须完成整个对应总线响应才返回0，自身有有限等待期限，返回 `KWT1_IO(-1)`、`KWT1_TIMEOUT(-2)`、`KWT1_CANCELLED(-5)` 区分故障。驱动的 `poll_limit` 限制 STATUS/provider 轮询次数，不能替代回调期限。

等待中取消由回调检查同一取消源处理。未接受的请求可由传输层撤销；已接受的请求必须先正确收回应答，或报告不确定状态并进入复位恢复。不得撤掉 accepted 请求后假定硬件没有执行。异步 provider 的取消与总线恢复是两件事。

`idle(opaque, cycles)` 提供有界 backoff，模型为64拍，再计一次回调成本；真实平台需实现并测量该等待。没有假定 DMA、层完成 IRQ 或总线主设备。驱动在每个 DATA 操作及每轮等待前检查取消，回调内部等待期间仍由回调负责检查。

## 任务与恢复

首次使用必须将整个 device 上下文清零，并填写回调/预算；同一 device/provider 串行执行，最多一个任务、一个 packet lease。

| 情况 | 返回/状态 | 下一步 |
|---|---|---|
| 正常冷任务 | 0；13次 acquire/release，完整输出并确认done | 可开始另一冷任务，重新装13包及输入 |
| 任务失败，ABORT写与空状态确认成功 | 原错误码；last_error保存原始原因，abort_error=0 | provider已cancel，可完整冷重载 |
| ABORT写或确认失败 | RESET_REQUIRED(-7)；recovery_required=1，last_error与abort_error分别保留 | 隔离，后续run与软件abort不再发总线请求/申请包 |
| 集成层硬复位、作废旧总线事务后 | 调用kwt1_after_hard_reset；核对空STATUS/frame_ready与ID | 确认成功才清除隔离，再完整冷重载 |

`kwt1_after_hard_reset` 不会替平台驱动复位引脚；调用前必须已经执行硬复位和传输层清理。仅清上下文、重复软件 ABORT 或重新申请参数不能绕过隔离。未完成的 packet 释放及 provider.cancel 在 run 的错误路径执行；独立调用公共 abort 的集成层仍需管理其自身 provider 所有权。

## 共享区与参数

common16576 B、每层61728 B，13包总757312 B；输入/输出各6336 B。只需一个61728 B staging，acquire(-1)后按layer0…11；PENDING 有界等待，成功lease保持到最后DATA排空且CRC/有效槽确认，随后release。错误包也恰好释放一次，cancel清除异步等待。CPU只搬运编码，不执行编码器算子。

模拟共享区的数据总74400 B；加128 KiB固件和16 KiB栈预留共221856 B，容量512 KiB。RV32 device/provider/packet上下文分别40/16/8 B，严格C99编译验证。地址、固件预留及栈预留不等于指定E203的链接镜像或栈高水位；这些需平台绑定后验证。

## SRAM

单口4096×16，地址12 bit；en/we/addr/wdata在上升沿采样。en=1,we=0时同步读，输出保持至下一次读；en=1,we=1时写入，旧读输出保持。en=0时不得因地址/数据变化而读写。宏数据无复位端口，控制器冷复位不得清空宏；每个冷任务显式重装所需内容。

未来技术宏必须由包装满足此语义，之后重新运行同一包装验收。测试模型初值是地址相关的非golden数据，不预置参数或答案。真实库读写延迟、使能极性、setup/hold、面积及功耗尚待资料。

## 验收映射

- 生产MMIO + 可控后端：6类定向场景、65次同拍交接，77接受=75应答+2硬复位丢弃；含40拍响应保持、17拍DATA背压、最终ACK邻接软件/硬件ABORT及reset。
- SRAM：同一台分别验证原行为路径与KWT_TECH包装路径，地址0/4095、同步读、保持、写输出不变及无数据复位。
- 真实完整RTL驱动：三配置各12类，14种供参/总线/取消/超时/清理故障后完整冷恢复；含已接受无响应、ABORT失败、确认失败和拒绝错误ID解禁。另有启动即持续总线失败的驱动隔离单元测试。
- 保留v2 observer的真实银行/MAC发射及流水计数断言：三配置验证总数、99-token尾块和暂停，不以最终分类Top-1替代码值检查。
- 整机通用网表闭环与正式总验收状态以本轮verification.json为准；MMIO可控后端台不能替代编码器或整机网表验证。
